# Geometric Measurements of the Axiom of Choice in Neural Proof Embeddings

Research code for the paper *"Geometric Measurements of the Axiom of Choice in
Neural Proof Embeddings."*

We partition all 471,260 Mathlib declarations by transitive dependence
on the axiom of choice and analyse tactic traces for 42,355 filtered
theorems. A label-free denoising encoder trained on constructive proofs
yields three complementary measurements—a k-NN anomaly score,
masked-token reconstruction loss, and density-superlevel
containment—that exhibit a common decline with dependency-graph
distance (AUC 0.847 at depth 2; chance by depth 9+). Estimating the
mixture weight from AUC alone predicts reconstruction loss and
containment across the non-anchor depth buckets.

The signature survives keyword, length, file, author, topic, detector,
full-source, and axis controls. Operationally, aesop solves constructive
theorems at roughly 13× the rate of classical ones, while a
ReProver–aesop hybrid compresses but does not close the gap.

Everything here is data-pipeline code: experiments, figures, and the numbers
behind the tables. There is no application.

## Repository layout

```
run_all.sh             One-shot end-to-end driver (inputs -> tables -> figures).
src/
  config.py            Central paths (override externals via env vars).
  lean/                Shared library: kernel graph, LeanDojo loaders,
                       proof/statement encoders, lake runner, source splicing.
experiments/           Flat, runnable scripts (one per table/figure/measurement).
  reproduce.py         Orchestrator — runs everything in dependency order.
  full_source/         Auxiliary appendix experiment: a BPE full-proof-source
                       encoder reproducing the depth law on raw text.
scripts/               Generators for the heavy external inputs (below)
                       + export_manifest.py.
manifest/              Committed provenance manifest (population + 251-sample CSVs).
results/
  data/                Generated artifacts (git-ignored).
  figures/             Generated figures (git-ignored).
```

## Environment

Python 3.12+.

```bash
python -m venv venv
venv/bin/pip install -r requirements.txt
```

### Run everything

`run_all.sh` drives the whole pipeline end to end — heavy inputs, main
pipeline, full-source appendix, and (optionally) the operational experiments:

```bash
bash run_all.sh                       # main pipeline + full-source appendix
RUN_HEAVY=1 bash run_all.sh           # also (re)build the kernel graph + LeanDojo
RUN_OPERATIONAL=1 bash run_all.sh     # also run aesop/ReProver (needs Lean)
SKIP_FULL_SOURCE=1 bash run_all.sh    # main pipeline only
```

### Or run pieces by hand

Run scripts from the repository root, either individually or via the
orchestrator:

```bash
venv/bin/python experiments/reproduce.py --list           # the full plan
venv/bin/python experiments/reproduce.py --dry-run
venv/bin/python experiments/reproduce.py --only-stage depth_law
venv/bin/python experiments/reproduce.py --skip-operational
venv/bin/python experiments/<script>.py                   # a single step
```

Apple Silicon note: training may use MPS, but the encoder/decoder *inference*
paths fall back to CPU (MPS has nested-tensor issues for `nn.TransformerEncoder`).

## Heavy external dependencies

These are **not** committed (too large) and are regenerated by the scripts in
`scripts/`. The pure-Python analysis (including `axis_comparison`, which reads
the kernel-graph file) needs only the first two; the operational experiments
additionally need a compiled Mathlib at run time. The author confound control
(`confound_authors_extract.py`) `git blame`s the Mathlib clone at the LeanDojo
commit `1bc7728a`, so it needs the **full git history** (a shallow clone won't
work; `scripts/setup_mathlib.sh` does a full clone).

| Input | Path | Size | How to obtain |
|---|---|---|---|
| Kernel dependency graph | `results/data/stage4v3/decl_graph_raw.jsonl` | ~280 MB | `python scripts/build_decl_graph.py --fetch-cache` (needs Mathlib) |
| LeanDojo Benchmark 4 traces | `results/data/leandojo/{train,val,test}.json` | ~940 MB | `python scripts/get_leandojo.py` (random split, traced @ Mathlib4 `1bc7728a`; the script verifies this commit) |
| Compiled Mathlib4 | `$MATHLIB_PATH` (default `../mathlib4`) | multi-GB | `bash scripts/setup_mathlib.sh` (pins v4.29.0-rc8 @ `9f0aee2`) |
| ReProver tactic generator | HuggingFace `kaiyuy/leandojo-lean4-tacgen-byt5-small` | ~300 MB | auto-downloaded by `transformers` on first use |

`config.py` resolves `MATHLIB_PATH` from an environment variable (default
`<repo>/../mathlib4`), so nothing is hardcoded to one machine.

### Build order for the heavy inputs

```bash
bash scripts/setup_mathlib.sh                       # clone + cache Mathlib
export MATHLIB_PATH="$PWD/../mathlib4"
python scripts/build_decl_graph.py --fetch-cache    # -> decl_graph_raw.jsonl (hours)
python scripts/get_leandojo.py                      # -> leandojo/{train,val,test}.json
```

Then `experiments/reproduce.py` runs the rest.

## Methodology notes

- **Label-free encoder.** The proof encoder is trained on constructive proofs
  only; the train/val/test split, the tactic-head vocabulary, and every
  hyperparameter are fixed without consulting any classical label. Classical
  proofs enter only as a held-out population to be measured.
- **Kernel-level partition.** A declaration is *classical* iff its proof term
  transitively uses `Classical.choice` (BFS over `getUsedConstants` edges).
  Depth is the shortest dependency distance to the axiom.

## Provenance & determinism

- **Pinned inputs.** The kernel graph is built from Mathlib4 `9f0aee2`
  (v4.29.0-rc8); the LeanDojo Benchmark 4 traces are pinned to Mathlib4
  `1bc7728a` and `scripts/get_leandojo.py` verifies that commit in the data.
- **Committed manifest.** `manifest/` ships the exact study population
  (`proof_population.csv`: name → is_classical, choice-depth, split) and the
  `operational_sample.csv` (the 251 aesop/ReProver theorems), so the population
  is inspectable without rebuilding any heavy input. Regenerate with
  `python scripts/export_manifest.py`.
- **Fixed seeds.** All randomness is seeded for deterministic reruns: the
  constructive train/val/test split and both encoders use seed 42
  (`np.random.seed` + `torch.manual_seed`); the operational sample uses seed 0;
  the full-source encoders use their seed argument. The depth-2 AUC (0.847),
  reconstruction-loss excess (+34.5%), and superlevel containment reproduce
  exactly from the committed inputs.
- **Not shipped (regenerated, by design).** Encoder checkpoints, embeddings,
  and the heavy data inputs are git-ignored — rebuild them with the pinned
  scripts above rather than downloading.

## Reproducibility status

The first time, building the kernel graph and tracing/obtaining LeanDojo are the
long poles (hours, plus a multi-GB Mathlib). Once those inputs and the trained
encoders exist, every table and figure in the main results is regenerated by
pure-Python scripts in minutes. The operational tables additionally require a
working Lean toolchain.
